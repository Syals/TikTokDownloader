# TikTok Explore Category Collection

## Goal
- Collect TikTok `/explore` category metadata and paginated videos for every
  category available to the authorized session.
- Deliver collection through pure HTTP requests after an evidence gate proves
  the real browser request can be replayed outside the browser.

## Scope
- In scope: Capture the real request chain generated by loading `/explore`,
  switching categories, and requesting additional pages.
- In scope: Convert `poc/tiktok_search_poc.py` from a search/discover probe
  into an Explore-specific diagnostic PoC.
- In scope: Discover category IDs from the captured request sequence, collect
  category videos with captured pagination, preserve each video's category
  membership, and create a media-URL-free download checklist.
- In scope: Add fixture-based tests for confirmed request and response shapes.

## Non-Goals
- Do not collect the For You recommendation feed. The current
  `poc/tiktok_explore_poc.py` calls `/api/recommend/item_list/` and is out of
  scope for this feature.
- Do not reuse search-only fields such as `keyword` or `search_id` for an
  Explore request.
- Do not use JSRPC, persistent browser automation, DOM/window shims, or TLS
  fingerprint emulation as the production collector.
- Do not commit cookies, tokens, signed URLs, signed request samples, or other
  credentials.

## Constraints
- The user authorized TikTok `/explore` as the target.
- Browser tooling MAY be used only to capture and compare real requests from
  the authorized session; it MUST NOT be a final runtime dependency.
- Existing `XBogus` and `XGnarly` implementations MAY be reused only after
  their output is compared with captured Explore requests.
- `sessionid`, `msToken`, and any server-issued cookies are session state, not
  pure-algorithm outputs. The implementation MUST handle them as credentials
  and MUST NOT write them to fixtures, logs, or source control.
- TikTok owns the endpoint, parameter, category, pagination, and response
  contracts. Uncaptured details remain unknown and MUST NOT be invented.

## Common Summary
- Objective: Replace the current guessed Explore probe with evidence-backed
  Explore category collection.
- Boundary: Final collection is Python pure HTTP with an authorized session;
  browser use ends after request-chain evidence is captured.
- Shared contracts: The evidence record defines the confirmed request shape;
  sanitized fixtures define the parser contract.
- Key dependency ordering: capture -> compare/replay -> diagnostic PoC ->
  implementation -> tests and documentation.
- Unknowns: The actual endpoint, category identifiers, pagination fields,
  response container, and any state dependencies are not yet confirmed.

## Context Facts
- `poc/tiktok_search_poc.py` currently probes search endpoints and
  `/api/explore/item/list/` with the same search payload and
  `from_page="search"`.
- `docs/tiktok-search-feasibility.md` records that the old Explore probe reused
  search parameters and returned JSON without `itemList`; it is not evidence
  that Explore collection is unavailable.
- `poc/tiktok_explore_poc.py` successfully processes the separate
  `/api/recommend/item_list/` recommendation feed and its media URLs.
- The repository already has pure Python `XBogus` and `XGnarly` helpers.
- A browser observation on 2026-07-29 confirmed that an anonymous `/explore`
  page fetches `GET /api/explore/item_list/` and renders category controls.
  This observation does not establish the authorized-session request contract.
- `reverse-records/explore_evidence.json` contains 15 sanitized, successful
  `GET /api/explore/item_list/` records from an authorized browser session.
  The records cover `categoryType` 119, 120, and 123; categories 120 and 123
  include both `pullType` 1 and 2, while category 119 includes `pullType` 2.
- The confirmed request shape has 39 query fields, including `categoryType`,
  `pullType`, `verifyFp`, and `user_is_login`. It has no observed
  `X-Bogus`, `X-Gnarly`, or `X-Dynosaur` query parameter.
- `explore-response.json` confirms a successful response has `itemList`,
  `cursor`, `hasMore`, and zero-valued status fields. Its item objects include
  `id`, `CategoryType`, `author`, `stats`, `video`, and `music`.
- `poc/tiktok_explore_collector.py` replays only HAR-captured request sequences.
  It discovers category IDs from those requests; no confirmed source for
  category names exists, so persisted category names are `null`.
- `poc/tiktok_explore_signed_poc.py` uses a captured parameter template and
  fresh `X-Bogus`/`X-Gnarly` output. On 2026-07-31 it collected 119, 120, and
  123 without `X-Dynosaur`; each category returned two successful pages, and
  120 returned three. A returned `play_url` downloaded as a non-empty MP4.

## User Outcomes
- An operator can collect videos grouped by the categories rendered on the
  authorized Explore page without manually copying video links.
- A failed pure HTTP replay produces a sanitized diagnostic record that states
  whether the failure is request-shape, session-state, or browser-environment
  dependent.

## Functional Requirements
- FR-1: The evidence phase MUST capture a successful initial Explore load,
  category switches for at least three categories, and one additional page for
  each captured category.
- FR-2: Each captured request record MUST identify the triggering page action,
  URL, method, query field names, request header names, response status,
  response header names, pagination fields, item container, and relevant
  `Set-Cookie` names. Credential values MUST be redacted.
- FR-3: The diagnostic PoC MUST send only fields evidenced for the selected
  Explore request and MUST save a sanitized comparison result for every
  browser-to-HTTP replay attempt.
- FR-4: The pure HTTP replay gate MUST verify non-empty video lists and
  evidence-confirmed page progression for at least three captured categories
  before any production collector is integrated. If the endpoint cursor remains
  static, progression MUST be verified from newly observed item ID hashes.
- FR-5: Once the replay gate passes, category discovery MUST use the confirmed
  live-page source and category pagination MUST retain `category_id` and
  `category_name` with every collected item.
- FR-6: The collector MUST deduplicate videos by TikTok item ID while retaining
  all category memberships for an item that appears in multiple categories.
- FR-7: If exact pure HTTP replay still fails while the browser request
  succeeds, implementation MUST stop before integration and report the minimum
  proven browser-only dependency. It MUST NOT add a browser runtime fallback
  under this specification.
- FR-8: If a new signing algorithm is required, the work MUST deliver a pure
  `algo.py` or `algo.js`, at least three redacted input/output fixtures, and a
  field-level verification record. No browser API may be a final algorithm
  dependency.

## Non-Functional Requirements
- NFR-1: All diagnostics and fixtures MUST be safe to commit: redact secrets,
  replace signed URL values, and retain only field names, types, lengths,
  hashes, and non-sensitive samples needed for comparison.
- NFR-2: Live network tests MUST be opt-in and excluded from the regular pytest
  suite. Parser and pagination tests MUST run entirely from sanitized fixtures.
- NFR-3: Python changes MUST pass `uv run ruff check .`,
  `uv run ruff format --check .`, and focused pytest coverage.

## Edge Cases
- Scenario: The API returns HTTP 200 with an empty body.
  Expected: Record status, body length, response header names, request-shape
  fingerprint, and failure classification; do not treat it as a valid empty
  category.
- Scenario: A response has a JSON object but no confirmed item container.
  Expected: Save a sanitized schema summary and stop pagination for that
  request shape.
- Scenario: A category response repeats the current cursor or repeats items.
  Expected: Stop that category safely and report the duplicate cursor or item
  IDs.
- Scenario: A category appears only after page interaction or lazy loading.
  Expected: Record the required interaction in the request-chain evidence;
  category discovery is not assumed to be static HTML.
- Scenario: A session cookie rotates during capture or replay.
  Expected: Record the cookie name and ordering dependency without storing its
  value; replay logic updates only in-memory session state.

## Shared Contracts
- Contract: `ExploreRequestEvidence`.
  Owner: evidence capture workstream.
  Consumers: diagnostic PoC, production collector, fixture tests.
  Notes: Contains redacted request-chain facts only; it is the source of truth
  until a confirmed collector contract replaces it.
- Contract: `ExploreCategoryItem`.
  Owner: production collector workstream.
  Consumers: metadata persistence and downloader.
  Notes: Exact fields are deferred until response capture. It must include an
  item ID and category membership fields.

## Acceptance Criteria
- AC-1: A sanitized evidence record contains three category request chains and
  one successful next-page request for each category.
- AC-2: The diagnostic PoC replays each recorded category through pure HTTP and
  records a non-empty confirmed item container plus pagination progression.
- AC-3: The integrated collector preserves category membership and does not
  emit duplicate item IDs as independent videos.
- AC-4: All committed fixtures, logs, and documentation contain no credentials
  or active signed media URLs.
- AC-5: Focused pytest tests and both repository Ruff checks pass.

## Implementation Outcome
- Added `poc/tiktok_explore_evidence.py` with a tested sanitizer for request
  evidence. It retains only endpoint paths, field names, types, lengths,
  response shape, and `Set-Cookie` names.
- The evidence tool can convert a private HAR export directly to sanitized
  Explore records. The HAR is read once and is never written back; only the
  generated evidence JSON is safe to retain.
- Generated `reverse-records/explore_evidence.json` from the 15 HAR entries
  and one separate response sample. All records mark
  `response.body_source="response_sample"`; the original HAR did not retain
  response bodies. The artifact retains category and pull-type values, but
  redacts cursors and every credential or dynamic signature value.
- Added `poc/tiktok_explore_replay.py` and verified six opt-in pure HTTP
  requests through the configured local proxy. `reverse-records/explore_replay.json`
  records non-empty responses and new item ID hashes for categories 119, 120,
  and 123. The cursor is static, so page progression is proven by hash-set
  changes rather than cursor changes.
- The browser evidence and pure HTTP replay gates are complete. Production
  collector integration is the remaining workstream.
- Added `poc/tiktok_explore_collector.py` as an independent `--live` collector.
  It reuses the proven raw-HTTP request plan and local session state, deduplicates
  in memory by raw `item.id`, retains all discovered category memberships, and
  writes only hashed item/author identifiers with no media URLs. The regular
  fixture suite covers request-plan limits, membership retention, deduplication,
  missing `itemList`, and preserved allowed headers.
- The Explore-focused suite passes (`12 passed`) and its Ruff checks pass. Full
  pytest remains blocked by `WinError 5` when existing download-bundle tests
  access the system pytest temporary directory. Full Ruff still reports 122
  pre-existing diagnostics, and the full format check finds five pre-existing
  unformatted files.
- Added `poc/tiktok_explore_signed_poc.py` for direct signed Explore collection.
  It emits local metadata with current media URLs, supports immediate optional
  downloads, and stops static-cursor pagination only after an empty/repeated
  page. It does not print, commit, or place URLs in evidence artifacts.

## Open Questions
- No confirmed category-name source exists in the captured protocol. Category
  metadata must retain `category_name: null` until it is independently captured.
- Should the independent collector be integrated into the terminal application
  after a category-name source and a safe media-download handoff are confirmed?
